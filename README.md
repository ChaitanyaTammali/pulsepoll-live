# Pulse — live polling

Pulse is a live polling app built as two separate projects: a React + Vite frontend and a Go + Gin backend. MongoDB stores accounts, polls, and durable votes. Redis holds the live counts and publishes updates to WebSocket clients. Poll owners sign in to create and manage polls; voters can use a shared poll link without an account.

## Install local prerequisites (Windows)

Install these directly on Windows; this project does not use Docker or containers:

- Go (the API is written for Go 1.23 or newer).
- Node.js LTS (includes npm).
- MongoDB Community Server, running on `localhost:27017`.
- Memurai Developer Edition, a Redis-compatible Windows service on `localhost:6379` for local development.

The MongoDB Windows installer can set up the server as a Windows service. Memurai's Developer Edition is for development and testing; it stops after 10 days and needs to be restarted. It is not licensed for production. See the [MongoDB Windows install guide](https://www.mongodb.com/docs/manual/tutorial/install-mongodb-on-windows/), [Go installation guide](https://go.dev/doc/install), and [Memurai download page](https://www.memurai.com/get-memurai).

If Windows Package Manager is available, these package IDs can be installed from PowerShell:

```powershell
winget install --id GoLang.Go --exact
winget install --id OpenJS.NodeJS.LTS --exact
winget install --id MongoDB.Server --exact
winget install --id Memurai.MemuraiDeveloper --exact
```

Restart PowerShell after installing Go and Node.js so their PATH updates take effect. Ensure MongoDB and Memurai services are running before starting the app.

## Run the backend

Open PowerShell in `backend/` and set the local environment values. Create a fresh private JWT key each time you start a local environment; use the same value across API instances:

```powershell
$bytes = New-Object byte[] 48
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:JWT_SECRET = [Convert]::ToBase64String($bytes)
$env:MONGO_URI = "mongodb://localhost:27017"
$env:MONGO_DATABASE = "pulsepoll"
$env:REDIS_ADDR = "localhost:6379"
go mod tidy
go run .
```

The API listens on `http://localhost:8080`. Check `http://localhost:8080/health` for its health response.

## Run the frontend

Open a second PowerShell window in `frontend/`:

```powershell
npm install
npm run dev
```

Open the local Vite URL shown in the terminal (normally `http://localhost:5173`). Vite proxies API and WebSocket requests to the Go server on port 8080. Build static frontend files with `npm run build`.

## Key decisions

- `frontend/` and `backend/` keep the two codebases separate. There are no Compose or container files.
- Signup, login, poll creation, and poll management require a signed JWT. Passwords use bcrypt; the JWT is stored in browser local storage. The public poll link uses a random 24-character slug.
- Request bodies are capped at 64 KB, parsed with unknown-field rejection, and validated before database access. Backend checks cover account data, poll text lengths, option count and uniqueness, route slugs, answer IDs, and voter session format. Votes store a hash of the voter ID and a unique MongoDB index prevents repeat votes for a poll session.
- MongoDB is the durable store. Redis hashes (`poll:<slug>:counts`) are the live count source; a cache miss rebuilds counts from stored votes with an atomic Redis seed script. A Redis Lua script deduplicates sessions and increments the selected count atomically, then Redis Pub/Sub pushes updated totals to WebSocket subscribers. This works across multiple API instances.
- The browser creates and remembers a random voter ID. Clearing browser storage or changing devices can create another voting session, so this is lightweight duplicate prevention rather than identity verification.

## Public deployment

`render.yaml` defines a native Go web service, a React static site, and a free Redis-compatible Key Value service. It does not use containers. In Render, create a Blueprint from this repository and provide `MONGO_URI` when prompted. MongoDB is not bundled with Render's Blueprint, so use a MongoDB Atlas URI (an Atlas free cluster is suitable for a demo) and allow the Render API service to connect. The frontend API URL and Redis URL are wired from the other Render services, and the API secret is generated by Render.

The free Render services are for demos and have restarts/sleep and data-persistence limits. Redis counts are rebuilt from durable MongoDB vote records after a cache reset. Use a production MongoDB and Redis plan with backups for production traffic. Local development still needs a Redis-compatible service at `localhost:6379`; Memurai Developer Edition installation failed on this computer, so that piece remains to be installed or replaced with a reachable Redis URL.
